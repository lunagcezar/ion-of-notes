# spec-130 - Tagged release artifacts

- Status: implemented (2026-11-24)
- Related: `spec-048`, `spec-050`, `spec-053`
- Review source: deferred release-artifact item in `docs/review-response.md`

## Purpose and scope

CI built a release binary and a container image but never published tagged
binaries. This spec adds `.github/workflows/release.yml`:

- triggered by `v*` tags;
- Linux `x86_64-unknown-linux-gnu` headless server tarball;
- Windows `x86_64-pc-windows-msvc` desktop executable and headless server
  archives;
- release notes generated by `gh release create --generate-notes`;
- assets uploaded with `gh release upload --clobber`, using the workflow
  `GITHUB_TOKEN` (no third-party release action).

Out of scope:

- code signing / notarization;
- macOS bundles;
- container registry publishing (Compose builds locally);
- installer packages.

## Acceptance criteria

P1. **Given** a `v*` tag, **then** the workflow builds the Linux server release
binary with `--locked`.

P2. **Given** a `v*` tag, **then** the Windows job builds the desktop and
headless server binaries.

P3. **Given** a successful build, **then** the archives are attached to the
GitHub release named after the tag.

P4. **Given** a re-run, **then** `--clobber` replaces the same asset names.

P5. **Given** a non-tag push, **then** the workflow does not run.

## Test scenarios

- YAML syntax review (CI runs the workflow only on tags).
- `cargo build --release --locked --no-default-features --bin ion-of-notes-server`
  locally.
- `cargo build --release --locked` locally.
- Full quality gate (unchanged).
